# Agent Learnings — mission-control (Jarvis)

## Standing rules
- Measure demand in mc.db before rating any external capability for Jarvis. Examples: 1 voice note since 06-25 (so R2T2 streaming ASR is no use); 0 `seo_*` calls in 30 days (so open-seo is no use). Same for a PR's premise: request rate vs the vendor limit (#37: 1/15 min vs 1/5 s), whether the configured ID still exists (#33), whether the incident recurred (#32: 0 in 30 days). Group activation is not usage. `active_groups LIKE '%seo%'` hit only broad turns that switch every group on, so print sample rows before counting activation as demand. For a "no demand today" verdict, write a trigger-gated findings doc (e.g. `docs/planning/seo-capability-findings-2026-09-23.md`) so a later step-up starts from facts.
- `task_trace_events` keeps only ~30 days. For longer horizons use `scope_telemetry` (from 2026-06-25). Run `.tables` + `pragma table_info(<t>)` before the first query. `tool.called` rows carry NULL `attrs`: the tool name is the `tool` COLUMN (10-09). Counts that go into a brief or a public doc name the binary (`/usr/bin/grep`; the agent-shell wrapper adds `-I` and skips binary-looking sources) and use `-w` for a name ("FEDERAL" inflated a name count, 10-09). Broken twice on 09-30 (recon guessed 6 columns; the wrap quoted a table that does not exist): the rule applies to a handover line as much as to a query. mc.db `created_at` columns (`tasks`, `jev_shadow`, `cost_ledger`) are UTC: compare `max(<col>)` with `date -u` before assuming a timezone; `claude plugin list` before adopting a vendor skill from a URL. Before any range predicate or `GROUP BY`: `COUNT(*)` + `MIN/MAX` + a `typeof`/`length` histogram of the column; 0 rows = "no population", say so (W3/S6 inventories 10-09; `reflection_baselines.task_type` holds request text, not an enum). Every count in a survey carries the grep/query that reproduces it (S6 R1 re-ran 36, found 9 mismatches).
- For a threshold re-tune, first reproduce the registered replay number from STORED answers, then walk forward. A fixed threshold that drifts does not mean periodic re-tuning helps: the Jev scope 0.70 walk-forward gave 92.6 % vs 92.0 % fixed, +2 turns of 299. Check whether a grid-search pick sits on the grid edge before trusting it.
- Replay/result files that carry user message text are sensitive: delete them when the readout closes, then check the backup paths too (`scripts/backup-state-bundle.sh` bundles only named `data/` subdirs).
- A version/pointer move owns every derived flag (certified, embedded): reset it in the LOWEST shared writer (`pointSkillAtVersion`), not in one caller — the boot scan and seed `skillSave` bypassed a caller-level decertify (#40 qa C1, #41 qa R2 W1). A write-back from a measurement keys on the exact version measured (`AND current_version_id = ?`; #41 qa C1: a slow run of a superseded version certified a failing newer one).
- A "never delivered / never happens" gate lives at the seam EVERY terminal path shares — enumerate each task status → handler (completed, blocked, needs_context, failed, cancelled, timeout) before claiming "never". The scope-ask gate sat on `handleTaskCompleted` only; the model ends a scope ask with STATUS: BLOCKED, so 34/34 real asks (08-24→09-24) went through `handleTaskFailed` verbatim while the invariant said NEVER. Same class as the pointer-move rule above: fix at the lowest shared point, not the caller you looked at. A prompt line the model ignores is fixed in the executor (structural), never with more prompt text: third instance 10-08 (planner "KB deliverables use the plain-string criterion" ignored by swarm children → `resolveCheckCwd`).
- Live-test scripts for Jarvis: pin `"agent_type": "fast"` when the task exercises host tools (file-shaped text → nanoclaw, which lacks them; task 9ce19a10); run every verification query once before handing the script over; put cleanup in `trap … EXIT` (an ambiguous-column query under `set -e` skipped the archive, task 0878a62a).
- After a ship, grep README/CLAUDE.md/docs (non-archive) + `~/.claude` memory for the changed function/section names and live counts and fix them in the same session (10-15: 6 stale living docs after the cache split, README/TOOL-CATALOG after Expand). Verify against the CURRENT tree, live state and the ARTIFACT ON DISK (a grader or gate that reads a registry a write path can bypass is judging a stale copy — 10-09), never an incident report, a PR's own base or a queued message: re-read today's code before writing prompt text about it (the SEC-02 `4b353ac` mount removal made a guard state a false fact); for a Jarvis PR run `git rev-list --count <branch>..origin/main`, trial-merge with `git merge-tree` and replay its test inputs on main (#32 redundant, #37 re-added removed code); check branch, worktree and PR state before acting on a queued request (the post-merge #41 request). An "owed" operator action repeated from memory/ROADMAP is a claim: read the artifact's own summary (`capturedAt`, score) before repeating it (eval baseline "re-capture owed" was 2 days stale, repeated 3x on 10-09). A cost or a blast-radius hit is attributed to a change only after the SAME probe runs on HEAD (`git archive HEAD src` timing 10-13 3q; the names-only db predicate on the pre-change classifier 10-13 3l): "pre-existing" is queued with its numbers, never folded into the diff.
- Bound every retry on a paid or certifying gate: retry only infrastructure outcomes (error/timeout), and count unfinished runs per `test_name` since that test's last pass — a per-version count let a passing sibling reset it every tick (#41 qa R1 W2, #43 qa R2); pin the bound with a 2-test mixed fixture.
- Diagnose from stored rows before reading code: task row (status, tool_calls) → `scope_telemetry` / `task_trace_events` (tool sequence of a working vs a failing task) → journal → the handler the status routes to; reproduce an upstream with a direct `curl` (#42, #47). Replay the stored corpus old-vs-new through a detector or term list BEFORE writing or trusting it — unit tests cannot see corpus-level false positives (#42: 34/34 asks caught, 0/6 real questions; #50: 34 of 36 alias hits were noise). A detector or cue patched twice is replaced by a closed rule pinned on the corpus misses AND over-fires in one pass (10-06 rating allow-list; 10-12 `isEnumeratedWorkOrder`). Swarm children are keyed in `task_trace_events` by their UUID sub-task ids (journal `[swarm] submitted sub-task`), not by `tasks.id`.
- Build a test fixture from the REAL producer and a real consumer, never from the rule under test; a green test whose fixture lacks the real shape proves nothing: WS3 env fixtures used `SECRET_<NAME>` while real refs are `SECRET_<SLUG>_<KEY>` (3 audit rounds passed), the exporter probed a cross-field schema one key at a time, so the first real export (10-12) dropped `capabilities` (run the WHOLE object), a round-trip test hand-wrote the inverse over fixtures shorter than every cap (go through the production functions, exceed each `slice(0, n)`), and a writer that feeds its own input needs an idempotence test (`export∘project∘export` byte-identical) (10-11, 10-12 twice). Prove each new test with a mutant that goes RED: rows sharing one `datetime('now')` second kept a per-version mutant GREEN until `ran_at` was staggered (#43); mutation-check each qa fold (#50). Timing tests: size each adversarial input so the slow (quadratic) code takes seconds instead of hanging CI and the pre-commit hook (vitest cannot interrupt a synchronous parse), keep the real-cap test for valid input only, and put the bound between the measured linear worst case and a mutant's time (#44: 800 ms vs ≤ 520 ms real / 984 ms mutant; #48). Paste a mutant's TEXT into a fold brief, never its label (10-09 twice: the implementer guessed variants). Tests bind to the REAL code: the test imports and calls the exported function (never re-implements its logic or mirrors its arithmetic in the assertions); the builder brief says so and the hand-back lists mutant → test pairs; the qa brief flags any assertion that mirrors the implementation (10-17 insights). Audit the operator's artifact (SQL, script, declaration) in the SAME round as the code, replayed through parse → loader → real spawn on a throwaway db (10-12 eurekams runbook shipped verified, not drafted). Audit budget per item: R1 full → one fold → R2 confirm; R3+ only when R2 reports a NEW Critical; a warnings-only round closes the item with the warnings logged in the queue; the builder brief states the budget (10-17: 3/3/4/3 rounds for four items).
- Host-mutating primitives (mount/umount/unshare/setns/pivot_root, cgroup, sysctl, firewall writes) are never executed on this VPS by a test, a mutant, a harness `--run` or an experiment — only in a disposable environment, or by the operator. - Flagged anomalies persist: any infra anomaly the agent notices (service down, 0-byte file, disk growth, failed job, a verdict contradicting delivered work) gets a numbered queue line with date, symptom and suggested fix BEFORE the session ends, whether or not the user replies (10-17 insights: a WA-down flag was lost in a session that exited).
