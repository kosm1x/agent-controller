# Agent Learnings — mission-control (Jarvis)

## Standing rules
- Measure demand in mc.db before rating any external capability for Jarvis. Examples: 1 voice note since 06-25 (so R2T2 streaming ASR is no use); 0 `seo_*` calls in 30 days (so open-seo is no use). Same for a PR's premise: request rate vs the vendor limit (#37: 1/15 min vs 1/5 s), whether the configured ID still exists (#33), whether the incident recurred (#32: 0 in 30 days). Group activation is not usage. `active_groups LIKE '%seo%'` hit only broad turns that switch every group on, so print sample rows before counting activation as demand. For a "no demand today" verdict, write a trigger-gated findings doc (e.g. `docs/planning/seo-capability-findings-2026-09-23.md`) so a later step-up starts from facts.
- `task_trace_events` keeps only ~30 days. For longer horizons use `scope_telemetry` (from 2026-06-25). Run `.tables` + `pragma table_info(<t>)` before the first query. `tool.called` rows carry NULL `attrs`: the tool name is the `tool` COLUMN (10-09). Counts that go into a brief or a public doc name the binary (`/usr/bin/grep`; the agent-shell wrapper adds `-I` and skips binary-looking sources) and use `-w` for a name ("FEDERAL" inflated a name count, 10-09). Broken twice on 09-30 (recon guessed 6 columns; the wrap quoted a table that does not exist): the rule applies to a handover line as much as to a query. mc.db `created_at` columns (`tasks`, `jev_shadow`, `cost_ledger`) are UTC: compare `max(<col>)` with `date -u` before assuming a timezone; `claude plugin list` before adopting a vendor skill from a URL. Before any range predicate or `GROUP BY`: `COUNT(*)` + `MIN/MAX` + a `typeof`/`length` histogram of the column; 0 rows = "no population", say so (W3/S6 inventories 10-09; `reflection_baselines.task_type` holds request text, not an enum). Every count in a survey carries the grep/query that reproduces it (S6 R1 re-ran 36, found 9 mismatches).
- For a threshold re-tune, first reproduce the registered replay number from STORED answers, then walk forward. A fixed threshold that drifts does not mean periodic re-tuning helps: the Jev scope 0.70 walk-forward gave 92.6 % vs 92.0 % fixed, +2 turns of 299. Check whether a grid-search pick sits on the grid edge before trusting it.
- Replay/result files that carry user message text are sensitive: delete them when the readout closes, then check the backup paths too (`scripts/backup-state-bundle.sh` bundles only named `data/` subdirs).
- A version/pointer move owns every derived flag (certified, embedded): reset it in the LOWEST shared writer (`pointSkillAtVersion`), not in one caller — the boot scan and seed `skillSave` bypassed a caller-level decertify (#40 qa C1, #41 qa R2 W1). A write-back from a measurement keys on the exact version measured (`AND current_version_id = ?`; #41 qa C1: a slow run of a superseded version certified a failing newer one).
- A "never delivered / never happens" gate lives at the seam EVERY terminal path shares — enumerate each task status → handler (completed, blocked, needs_context, failed, cancelled, timeout) before claiming "never". The scope-ask gate sat on `handleTaskCompleted` only; the model ends a scope ask with STATUS: BLOCKED, so 34/34 real asks (08-24→09-24) went through `handleTaskFailed` verbatim while the invariant said NEVER. Same class as the pointer-move rule above: fix at the lowest shared point, not the caller you looked at. A prompt line the model ignores is fixed in the executor (structural), never with more prompt text: third instance 10-08 (planner "KB deliverables use the plain-string criterion" ignored by swarm children → `resolveCheckCwd`).
- Live-test scripts for Jarvis: pin `"agent_type": "fast"` when the task exercises host tools (file-shaped text → nanoclaw, which lacks them; task 9ce19a10); run every verification query once before handing the script over; put cleanup in `trap … EXIT` (an ambiguous-column query under `set -e` skipped the archive, task 0878a62a).
- A red `main` is an open defect, never a baseline: run `gh run list --branch main --limit 3` before any merge and fix or log the red. #41–#43 merged over a main red since ≤09-22 that memory had normalized ("compare a PR's failing set to main's"), and a known-red set hid a timing flake until #44 cleared it.
- Verify against the CURRENT tree, live state and the ARTIFACT ON DISK (a grader or gate that reads a registry a write path can bypass is judging a stale copy — 10-09), never an incident report, a PR's own base or a queued message: re-read today's code before writing prompt text about it (the SEC-02 `4b353ac` mount removal made a guard state a false fact); for a Jarvis PR run `git rev-list --count <branch>..origin/main`, trial-merge with `git merge-tree` and replay its test inputs on main (#32 redundant, #37 re-added removed code); check branch, worktree and PR state before acting on a queued request (the post-merge #41 request). An "owed" operator action repeated from memory/ROADMAP is a claim: read the artifact's own summary (`capturedAt`, score) before repeating it (eval baseline "re-capture owed" was 2 days stale, repeated 3x on 10-09).
- Temporary worktrees: create them beside the main checkout (`/root/claude/<name>-tmp`, not the scratchpad — `shell.test.ts` resolves `cd ..` on the real FS) and remove them after the push; from a worktree pass `MC_DB_PATH=/root/claude/mission-control/data/mc.db` explicitly (the inherited relative path resolves against the worktree); never run a `mc-ctl` copy as-is (`PROJECT_DIR` is hard-coded to the live checkout — copy it to scratch with `PROJECT_DIR` sed-replaced, and seed scratch DBs through `initDatabase` in a tsx script, since mc-guard blocks `rm`/write `sqlite3` on a path ending `mc.db`).
- Bound every retry on a paid or certifying gate: retry only infrastructure outcomes (error/timeout), and count unfinished runs per `test_name` since that test's last pass — a per-version count let a passing sibling reset it every tick (#41 qa R1 W2, #43 qa R2); pin the bound with a 2-test mixed fixture.
- Diagnose from stored rows before reading code: task row (status, tool_calls) → `scope_telemetry` / `task_trace_events` (tool sequence of a working vs a failing task) → journal → the handler the status routes to; reproduce an upstream with a direct `curl` (#42, #47). Replay the stored corpus old-vs-new through a detector or term list BEFORE writing or trusting it — unit tests cannot see corpus-level false positives (#42: 34/34 asks caught, 0/6 real questions; #50: 34 of 36 alias hits were noise). A detector or cue patched twice is replaced by a closed rule pinned on the corpus misses AND over-fires in one pass (10-06 rating allow-list; 10-12 `isEnumeratedWorkOrder`).
- Build a test fixture from the REAL producer and a real consumer, never from the rule under test; a green test whose fixture lacks the real shape proves nothing: WS3 env fixtures used `SECRET_<NAME>` while real refs are `SECRET_<SLUG>_<KEY>` (3 audit rounds passed), the exporter probed a cross-field schema one key at a time, so the first real export (10-12) dropped `capabilities` (run the WHOLE object), a round-trip test hand-wrote the inverse over fixtures shorter than every cap (go through the production functions, exceed each `slice(0, n)`), and a writer that feeds its own input needs an idempotence test (`export∘project∘export` byte-identical) (10-11, 10-12 twice). Prove each new test with a mutant that goes RED: rows sharing one `datetime('now')` second kept a per-version mutant GREEN until `ran_at` was staggered (#43); mutation-check each qa fold (#50). Timing tests: size each adversarial input so the slow (quadratic) code takes seconds instead of hanging CI and the pre-commit hook (vitest cannot interrupt a synchronous parse), keep the real-cap test for valid input only, and put the bound between the measured linear worst case and a mutant's time (#44: 800 ms vs ≤ 520 ms real / 984 ms mutant; #48). Paste a mutant's TEXT into a fold brief, never its label (10-09 twice: the implementer guessed variants).
- Claims from agents: An auditor's fix is a proposal: check every fold brief against the operator rulings AND the data model before dispatching it. 09-30 twice: "A2A `interactive:false`" contradicted ruling R6; "same task_id for the follow-up reply" would never match because the router writes the user turn before the reply exists (27/27 live tasks). Both caught by the implementer, not by me. A paste line for the operator is a CLAIM until replayed — FOUR misses (09-11 Caddy block; 09-29 "Ejecuta ahora el schedule"; 09-30 `mc-ctl db "$(cat file.sql)"` + a table that does not exist; 10-01 an unmount script verified on selection only, which removed 12 original system mounts). Every handover line carries "Verified: <selection | effect> on <what>"; a line whose EFFECT was not replayed is labelled a draft; a line my own session was DENIED is never handed over unchanged. Feed SQL files through stdin (`sqlite3 db "$(cat f.sql)"` breaks on a leading `--` comment, parsed as an option, 10-12); verify the count after the operator says "done". Audit the operator's artifact (SQL, script, declaration) in the SAME round as the code, replayed through parse → loader → real spawn on a throwaway db (10-12 eurekams runbook shipped verified, not drafted).
- Host-mutating primitives (mount/umount/unshare/setns/pivot_root, cgroup, sysctl, firewall writes) are never executed on this VPS by a test, a mutant, a harness `--run` or an experiment — only in a disposable environment, or by the operator. Such a workstream runs ALONE, with a hold point (agent writes code + tests, hands back, waits for GO), a brief that names the incident protocol (next tool call = hand-back starting `INCIDENT:`; never remediate), and tests that create their own namespace so no mutant of the code under test can reach the host. Host remediation: read-only diagnosis, predicted collateral, reboot offered as an option. Default-to-action and background fan-out do not apply here.
- Repo code run outside vitest writes to LIVE paths by default (KB mirror `/root/claude/jarvis-kb`, `decisions/`, Drive/pgvector sync): any brief that lets an agent run scripts, tests or MUTANTS against a scratch db sets `JARVIS_KB_MIRROR_DIR=<scratch>` in every process, builds synthetic dbs with the `sqlite3` CLI (never `initDatabase`), and never runs a mutant that removes a safety gate on the live target. "mc.db read-only" does not protect the mirror. Twice on 10-04 (`e9d7efb`).
- Data reaching an EXTERNAL caller (CRM, A2A, API) is opt-in per row (a tag the operator sets from a chat root), never a path tree: three audit rounds on 09-30 found litigation, health, preferences and investment rows under `knowledge/` and `projects/`, a health file under `projects/plan-2027/health/`, a competitor staff directory under `projects/expansion-crm/` and a "Confidencialidad: Alta" doc under `knowledge/domain/`. Before any allow-list, `SELECT path, title` under the prefix and grep the content for people/health/finance/e-mails. `interactive:false` is a gate BYPASS, never a safe mode: an API caller is refused by the default-interactive task with no chat origin.
- A replay benchmark names what it compares against: pin the pool window (`--before=<cutover>`), print the reference model(s) and the per-position cache read in the DRY run and the summary, neutralise the live canary's `SONNET_*` after the `/proc` copy, and report every paid metric two ways (SDK-reported vs usage × price table: the 1.6× gap showed only when both were printed). The judge model is never the candidate, and every arm model gets one cheap reachability call before the loop (10-07: Opus 5.5 arms 400'd on all 20 tasks; the default grader was that same model). Twice: 09-29 position confound, 10-07 reference flip.
- Git commands run alone: no `grep` or pipe in the same Bash call (the hook-bypass guard scans the whole string), and `cd <repo> && git push origin main` is its own call (git-auth-guard reads the SESSION cwd's remote). Logged 09-23 and 09-29. `git fetch` before the push at the end of a long session: `main` moved twice on 10-03 (operator PRs merged from the cloud); read `git log HEAD..origin/main` and the diffstat, then merge (a dirty tree with the never-commit files makes rebase stash `.env.example`). Pre-commit hook output: filter with `grep -E "×|FAIL|Tests "`, never `tail -N` (the failing test name scrolls off; 10-09 twice, 10-12), then run the suspect file scoped.
- An "operator-only" path is a MECHANISM the task cannot forge, never a convention or a task-controlled property: key gates on kernel-assigned facts (cgroup login-session allow-list), not on `isTTY` (faked by `script -qec`/`pty.spawn`) or a string deny (`project''-create`); when a prompt input moves from a constant to a stored value, enumerate every WRITER of that value and its confirmation level; probe `validateShellCommand` with the obfuscated AND quoted forms before calling any guard closed; a guard audit hunts bypasses on the changed alternatives, re-running the suite is not the audit (10-11: 4b pointer, 5a scripts; 10-12: R1 C1 quoted-span bypass, queue 3q). A boundary over a moving set (secret-shaped env names, deny verbs) is allow-by-source; a deny-list is defence in depth only (WS3 R2: 33 secret-shaped service names passed one; 3c: `c''rontab` passed the deny list). An auto-mode classifier denial is final (`.env*` incl. `.env.example`; an edit that weakens an operator gate = Security Weaken): stop and hand the operator the exact line, never retry or route around (10-07, 10-09, 10-12).
