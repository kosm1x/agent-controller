## Standing rules
- Measure demand in mc.db before rating any external capability for Jarvis. Examples: 1 voice note since 06-25 (so R2T2 streaming ASR is no use); 0 `seo_*` calls in 30 days (so open-seo is no use). Same for a PR's premise: request rate vs the vendor limit (#37: 1/15 min vs 1/5 s), whether the configured ID still exists (#33), whether the incident recurred (#32: 0 in 30 days). Group activation is not usage. `active_groups LIKE '%seo%'` hit only broad turns that switch every group on, so print sample rows before counting activation as demand. For a "no demand today" verdict, write a trigger-gated findings doc (e.g. `docs/planning/seo-capability-findings-2026-09-23.md`) so a later step-up starts from facts.
- `task_trace_events` keeps only ~30 days. For longer horizons use `scope_telemetry` (from 2026-06-25). Run `.tables` + `pragma table_info(<t>)` before the first query. `tool.called` rows carry NULL `attrs`: the tool name is the `tool` COLUMN (10-09). Counts that go into a brief or a public doc name the binary (`/usr/bin/grep`; the agent-shell wrapper adds `-I` and skips binary-looking sources) and use `-w` for a name ("FEDERAL" inflated a name count, 10-09). Broken twice on 09-30 (recon guessed 6 columns; the wrap quoted a table that does not exist): the rule applies to a handover line as much as to a query. mc.db `created_at` columns (`tasks`, `jev_shadow`, `cost_ledger`) are UTC: compare `max(<col>)` with `date -u` before assuming a timezone; `claude plugin list` before adopting a vendor skill from a URL. Before any range predicate or `GROUP BY`: `COUNT(*)` + `MIN/MAX` + a `typeof`/`length` histogram of the column; 0 rows = "no population", say so (W3/S6 inventories 10-09; `reflection_baselines.task_type` holds request text, not an enum). Every count in a survey carries the grep/query that reproduces it (S6 R1 re-ran 36, found 9 mismatches).
- For a threshold re-tune, first reproduce the registered replay number from STORED answers, then walk forward. A fixed threshold that drifts does not mean periodic re-tuning helps: the Jev scope 0.70 walk-forward gave 92.6 % vs 92.0 % fixed, +2 turns of 299. Check whether a grid-search pick sits on the grid edge before trusting it.
- Replay/result files that carry user message text are sensitive: delete them when the readout closes, then check the backup paths too (`scripts/backup-state-bundle.sh` bundles only named `data/` subdirs).
- A version/pointer move owns every derived flag (certified, embedded): reset it in the LOWEST shared writer (`pointSkillAtVersion`), not in one caller — the boot scan and seed `skillSave` bypassed a caller-level decertify (#40 qa C1, #41 qa R2 W1). A write-back from a measurement keys on the exact version measured (`AND current_version_id = ?`; #41 qa C1: a slow run of a superseded version certified a failing newer one).
- A "never delivered / never happens" gate lives at the seam EVERY terminal path shares — enumerate each task status → handler (completed, blocked, needs_context, failed, cancelled, timeout) before claiming "never". The scope-ask gate sat on `handleTaskCompleted` only; the model ends a scope ask with STATUS: BLOCKED, so 34/34 real asks (08-24→09-24) went through `handleTaskFailed` verbatim while the invariant said NEVER. Same class as the pointer-move rule above: fix at the lowest shared point, not the caller you looked at. A prompt line the model ignores is fixed in the executor (structural), never with more prompt text: third instance 10-08 (planner "KB deliverables use the plain-string criterion" ignored by swarm children → `resolveCheckCwd`).
- Live-test scripts for Jarvis: pin `"agent_type": "fast"` when the task exercises host tools (file-shaped text → nanoclaw, which lacks them; task 9ce19a10); run every verification query once before handing the script over — and before writing it into a queue/watch line (10-25: the 4ak watch said match `content_hash` against `gdelt:goldstein_avg:*`, but the column is a HASH; the next session would have read 0 rows as a clean watch); put cleanup in `trap … EXIT` (an ambiguous-column query under `set -e` skipped the archive, task 0878a62a).; same class 10-25 evening: the 4ak line said `./mc-ctl task 12493` but `mc-ctl task` selects on the UUID `task_id`, so the row id matched nothing — read the command's usage text (`mc-ctl task <task_id>`) before handing an operator line
- After a ship, grep README/CLAUDE.md/docs (non-archive) + `~/.claude` memory for the changed function/section names and live counts and fix them in the same session (10-15: 6 stale living docs after the cache split, README/TOOL-CATALOG after Expand). Verify against the CURRENT tree, live state and the ARTIFACT ON DISK (a grader or gate that reads a registry a write path can bypass is judging a stale copy — 10-09), never an incident report, a PR's own base or a queued message: re-read today's code before writing prompt text about it (the SEC-02 `4b353ac` mount removal made a guard state a false fact); for a Jarvis PR run `git rev-list --count <branch>..origin/main`, trial-merge with `git merge-tree` and replay its test inputs on main (#32 redundant, #37 re-added removed code); check branch, worktree and PR state before acting on a queued request (the post-merge #41 request). An "owed" operator action repeated from memory/ROADMAP is a claim: read the artifact's own summary (`capturedAt`, score) before repeating it (eval baseline "re-capture owed" was 2 days stale, repeated 3x on 10-09). A cost or a blast-radius hit is attributed to a change only after the SAME probe runs on HEAD (`git archive HEAD src` timing 10-13 3q; the names-only db predicate on the pre-change classifier 10-13 3l): "pre-existing" is queued with its numbers, never folded into the diff. Swarm children are keyed in `task_trace_events` by their UUID sub-task ids (journal `[swarm] submitted sub-task`), not by `tasks.id`.
