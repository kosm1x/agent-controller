## DOCTRINE: frontmatter renderer — the audit question is "which fields carry free text?"
`renderFrontmatter` (adr-writer.ts:156-175) hand-rolls YAML (`${key}: ${value}`, no quoting/escaping). This is SAFE here — and the reason is the load-bearing audit insight: every frontmatter value is an enum / number / derived label / controlled identifier (capability = registered tool name PRIMARY KEY). The ONLY genuinely free-text/external field — the decision `payload` — is correctly rendered into a fenced ```json code block in the BODY (via `prettyJson`), NOT into frontmatter. So no YAML-break / no second-`---`-injection path exists in this phase. The prompt's flagged concern `status: Superseded by 8` (spaces, unquoted) IS valid YAML — spaces are fine in a plain scalar; only `: `+space, or a leading YAML-indicator char, would break it, and no value here can produce those. When auditing ANY frontmatter/structured-header renderer: enumerate the fields, ask which can carry external/operator free text; if any do (or could after a future caller change), it needs a real serializer or quoting — the delimiter-only "well-formed" test (test:116-117 checks `---` delimiters, not YAML-parse validity) won't catch it.

## DOCTRINE: slug path-traversal airtight via `[^a-z0-9]+`→`-`
`adrFilename` (adr-writer.ts:146-152) builds `logs/decisions/<id>-<slug(capability)>-<tail>.md`. Traced hostile inputs — `"../../etc/passwd"`→`etc-passwd`, punctuation-only→`decision`, unicode/CJK/Cyrillic→stripped→`decision`. Airtight because `slug` (line 115-122) lowercases→NFKD→`replace(/[^a-z0-9]+/g,"-")` strips EVERY `/` and `.`, so `..` and absolute-path leading-`/` cannot survive; `(out||"decision")` + trailing-dash-strip kills the degenerate-empty case. id is typed `number` (INTEGER PK) — can't inject path chars. The whitelist-reduce (`[^a-z0-9]`) is the right pattern vs a blacklist of bad sequences.
