Headline findings:

1. **Agent SDK is 35 published releases behind (0.3.245 → 0.3.288).** The bump needs `eval:gate` (follow-up L1, VPS). Reading 0.3.273 (Stop hook timeout now "counts as no decision") surfaced a gap that exists already at the current pin: we wire exactly one Stop hook, so a gates hook that runs past its 180 s timeout lets the model stop with no gates trace under both the old and the new semantics. It gets its own small cloud follow-up (L5), not tied to the bump.
2. **Managed Agents "outcomes" confirm the W1 design** (separate-context grader, per-criterion scoring) and add four details W1 lacks: explicit budget-exhausted and interrupted results, start/iteration events, and rubric-from-a-known-good-example. Input to S3.
3. **MCP:** the current spec is 2026-07-28 (stateless rewrite, handshake removed). No SDK negotiates it yet: installed 1.29.0 and latest v1 1.32.0 both top out at 2025-11-25. Our bridge drops `structuredContent` and resource links, keeping text only (follow-up L2, cloud).
4. **A2A:** upstream is at 1.0.1; ours matches no released version (camelCase methods, `/.well-known/agent.json`, `type`-discriminated parts, no version header). A conformant peer gets `-32601` both ways. Whether anyone uses it is unverified (follow-up L3, VPS data then operator ruling).
5. **Best idea to borrow from the frameworks:** snapshot Prometheus after every goal (LangGraph durability modes, MAF checkpoints with pending requests), plus a snapshot format version and a pending-approval field. That also unblocks run-wide approvals in non-fast runners. Input to W2.
6. **Observability:** OTel GenAI conventions are still Development with no schema URL. Borrow the `gen_ai.*` vocabulary and the `gen_ai.evaluation.result` shape now; defer an OTLP exporter (follow-up L4).

## Answers to the two version questions

**MCP: which spec do we speak, and is it current?** The current spec revision is **2026-07-28** (`docs/docs.json` labels it "Version 2026-07-28 (latest)"; `schema/draft/schema.ts` sets `LATEST_PROTOCOL_VERSION = "2026-07-28"`; the `draft` changelog is empty). Our installed `@modelcontextprotocol/sdk` **1.29.0** declares `LATEST_PROTOCOL_VERSION = '2025-11-25'` and `SUPPORTED_PROTOCOL_VERSIONS = [2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05, 2024-10-07]` (`node_modules/@modelcontextprotocol/sdk/dist/esm/types.js:2-4`, checked on this branch), so it negotiates up to **2025-11-25**. The latest v1 release, **1.32.0** (2026-10-02), still sets 2025-11-25. A v2 line exists (`@modelcontextprotocol/{core,client,server}` 2.0.0 on 2026-07-27, 2.3.0 on 2026-10-02; requires `zod ^4.2.0` and node >= 20); its core bundle carries schemas for `server/discover`, `input_required` and `subscriptions/listen`, but its latest-version constant is also 2025-11-25. So no SDK speaks 2026-07-28 yet; we are one revision behind the spec and current with every SDK. The gap that matters now is not the version but b1 (we drop non-text results).

**A2A: which version is `src/a2a/`?** None. "v2.2" is an internal milestone row (`docs/PROJECT-STATUS.md:102`), not a protocol version, and `src/a2a/` carries no `protocolVersion` or `A2A-Version` anywhere. Upstream released 0.2.6 (2025-07-17), 0.3.0 (2025-07-30), 1.0.0 (2026-03-12) and 1.0.1 (2026-05-26; the a2a-protocol.org page read the same day still said "Latest Released Version 1.0.0", the changelog lists the 1.0.1 patch). Ours mixes generations: the card path `/.well-known/agent.json` is the 0.2.x path (moved to `agent-card.json` in 0.3.0); the method names `sendMessage` / `getTask` are camelCase, matching neither 0.2/0.3 (`message/send`) nor 1.0 (`SendMessage`); parts use a `type` discriminator (0.2/0.3 use `kind`, 1.0 has none); states are lowercase with no input-required or auth-required; stream events carry `final` (removed in 1.0). A conformant 0.3 or 1.0 peer would get JSON-RPC `-32601` (method not found) calling us, and we would get the same calling it. Evidence: c1 to c4 above.
