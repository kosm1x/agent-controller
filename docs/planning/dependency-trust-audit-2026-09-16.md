## 8. The three cases, re-traced after the gate

- **A — agent adds a package to solve a task.** Trigger: `shell_exec npm install x` or `npx x`. ## 12. Python path behind a wrapper (2026-10-21, operator ruling after a 3-strike stop)

Trigger: three `[shell-guard] BLOCKED` refusals 2026-10-21 02:51–02:55 UTC (tasks 12230/12232/12233; 3 of 193 shell-guard refusals since 09-23, the only ones of this class): `xvfb-run -a /tmp/pr_test/bin/python /tmp/pr_test/test_pr.py`, the same after `cd /tmp/pr_test &&`, and `timeout 55 xvfb-run -a ./bin/python test_pr.py`. Rule (route 1, structural): for the ARGUMENT rule only, a token whose basename is `python` or `python3` (regex `/^python3?$/`) is an interpreter, not a manager binary — unless a copy word (`COPY_WORDS`) appears anywhere in the segment (a hoisted `copySeen`, computed in the same pass as `lastPm`; it keeps `xvfb-run -a cp <p>/python zz` and `… ln -s <p>/python zz` refused, where `cp` is not at command position). String-only: no fs call, no cwd, no venv check, no cap. Unchanged: `PM_WORD_RE`, `pmWord`, `isPmBinaryPath`, `PM_ENTRY_RE`, the `lastPm` pass, the COPY rule (`cp /usr/bin/python3 zz`, `timeout 5 cp <p>/python zz`, bare `cp python3 zz` refused), every verb rule (`<p>/python -m pip install x` and `xvfb-run -a <p>/python -m pip uninstall -y x` refused at the `pip` token; `<p>/pip install x` too), the PATH/env rules, and every non-python manager path (`xvfb-run -a /usr/bin/npm ls`, `xvfb-run -a /opt/python3/bin/pip3 list` — the shape is the basename, not a `python` directory).

Why it is safe — bare-name parity: the argument rule exists to stop minting an unshimmed manager alias (`node -e "symlinkSync('/usr/bin/npm',…)"`, still refused). Python is not shimmed (`pm-shim/` has no python entry), and every command this exemption newly allows has a twin with the path replaced by `python3` that HEAD already allows (qa R4 replay: 388 allowed lines unchanged, the 3 target refusals newly allowed, nothing else).
