# Screenwriting workflow and the story bible

**Read this when:** starting or resuming a screenplay, play or series project, deciding what comes next, or sequencing the other docs.
**Source:** distilled 2026-09-12 from jtydhr88/screenwriting-skills `sw-workflow` (method only); underlying books: none — a meta-skill; craft sources are the docs it routes to.
**Pairs with:** knowledge/screenwriting/02-premise-theme-logline.md, knowledge/screenwriting/03-story-structure.md, knowledge/screenwriting/04-character-and-conflict.md, knowledge/screenwriting/05-dialogue.md, knowledge/screenwriting/06-scene-craft.md, knowledge/screenwriting/07-format-fountain-adaptation.md, knowledge/screenwriting/08-series-structure.md, knowledge/screenwriting/09-series-engine-and-bible.md, knowledge/screenwriting/10-writers-room-and-notes.md, knowledge/screenwriting/11-half-hour-comedy.md, knowledge/screenwriting/12-terms.md, knowledge/screenwriting/13-short-form-commercial.md

Two jobs: **sequence** (which doc at which stage, deliverable, exit check) and **persist** (conclusions go into `story-bible.md` so the next session continues).

## 1. Session protocol

**Start**
1. Look for `story-bible.md` in the working (or user-named) directory.
2. Found: read only "Current stage", "Settled decisions", "Decision log"; restate in three sentences (project, stage, last decision, next step); continue; never reopen settled decisions unless the user does.
3. One-off deliverable, no follow-up session (plan, pitch, one-pager, outline): no bible — run the stage table in-session.
4. Not found, ongoing: pick the entry path (§3), create the bible (§7) with only "Project info" and "Current stage" filled. At most four questions; infer, mark "(to confirm)".

**During:** each deliverable goes into its bible section at once and "Current stage" advances; a changed settled decision gets a log line (date, what, why); the bible stays readable in one sitting (~25K tokens) — conclusions only; outlines, treatments, scripts are separate files (name + status).

**End:** bible current; last line "Next step:" + one sentence.

## 2. Feature / stage-play stage table

| # | Stage | Doc | Deliverable (bible section) | Advisory exit check |
|---|---|---|---|---|
| 0 | Start / resume | this doc | project info, entry path, stage | type, length, audience known |
| 1 | Premise | 02 | spark, theme sentence, what-if, **premise** (trait + leads to + outcome), **controlling idea** (value + cause), third track (desire vs. false belief), dramatic core, one-sentence story, logline | one premise; tellable to a stranger; collapses without the core; theme word set |
| 2 | Structure | 03 | ending, opening, plot points I/II, midpoint kind (false victory/defeat), BS2 page table, act ratios, subplot vs. controlling idea | four fixed points known; setup ≤25 pages; midpoint mirrors all-is-lost; act three shortest |
| 3 | Character | 04 | three-dimension table, category, stance on theme, unity-of-opposites binding, antagonist's knife, growth ladder, primal scene | hero most dimensional; antagonists combined outstrip hero; no two of one type; self-as-opponent facet; no convenient rescue |
| 4 | Scene list | 06 + 07 | step outline (line + value turn + slot per scene), 40-card board, image system, optional treatment | every scene turns a value; act three >2 cards; adjacent scenes share a transition; no pure exposition |
| 5 | First draft | 05 + 07 | script (`.fountain` for Hollywood format; others per 07), pages, daily progress | pages within ±15%; format rules pass; dialogue identifiable with names covered |
| 6 | Revision | all checklists | revision targets, per-item record, draft number | structure 13, character 14, dialogue 14, scene 13, format (A 12 + adopted convention) all run |
| 7 | Submission | industry skill (not distilled) | logline + synopsis, pitch, targets, credit/registration | PROBLEM seven elements pass; one-liner survives the stranger test |

**Rollback:** dialogue that will not write at 5 is a hole at 3 or 1 — patch, log.

## 3. Entry paths

| Situation | Start at | Handling |
|---|---|---|
| Feature / play from zero | 0 → 1 → … → 7 | standard |
| Existing draft to revise | reverse-fill 1–3 from the draft, then 6 | items the draft lacks = the revision list |
| Adapting novel / play / true story | 0 → four adaptation questions (07) → 1 → 2 … | stage 1 names where the source conflict sits and what to reinvent; true story: rights |
| Short film / one-act | 1 → 2 (opening-development-turn-close + eight ending methods replace BS2) → 3 → 5 | 10–15 cards; ≤5 characters; core first; commercial: 13 |
| One idea, unsure | 1 (to the one-sentence story) → PROBLEM check | pass → 2; fail → new idea, log the rejected one and why |
| TV / streaming / pilot / season | series table S0–S7 | engine and bible before script; proposal format in 07 |
| Half-hour comedy | series table, S2 and S5 via 11 | pages, format, joke density all switch |
| Industry question | 7 directly | no bible |

Not covered: Chinese-opera forms and mainland-China production/approval chains.

## 4. Series stage table

A series is a repeatable **engine** plus unresolved tension, cut by act outs, bible-first, collective, showrunner-led. **Prove the engine runs a hundred episodes before writing episode one.**

| # | Stage | Doc | Deliverable | Advisory exit check |
|---|---|---|---|---|
| S0 | Start / resume | this doc | platform and format (broadcast/cable/streaming; hour/half-hour; episodes, seasons), entry path | who decides act count (ad breaks or you); pages |
| S1 | Engine | 09 + 02 | thematic opposition, four franchise elements (concept/conflict/theme/story pattern), core question as a process sentence, tacit contract, 5–6 story areas | fail if no three episodes follow the pilot or story areas share source/outcome |
| S2 | Web and season arc | 09 + 04 | 3–4 leads (≤1 page each) + conflict web, season-arc grid, season question, tentpoles | leads never smile and agree; each can lose something; finale answers this year's question |
| S3 | Documents | 09 | logline + springboard, pitch document / series format, bible tier, storyline docs | a stranger can restate what happens each week |
| S4 | Pilot and episode | 08 (half-hour: 11) | pilot type (premise/typical/hybrid), act count + page anchors, act-out list, A/B/C entry-exit, 17-column story map | each act out poses a new question; C story never closes an act; an invisible act break cites three grounds |
| S5 | Break story | 10 + 06 | beat sheet (6–7 scenes per act) → locked outline; six-week schedule | one beat per scene with act position; ending changes return to the outline |
| S6 | Draft and rewrite | 05 + 07 + 10 | script (teaser/ACT or day markers), pages, warm/cold-read records | hour 48–63 pages, single-cam ≈30, multi-cam ≈50; a cold reader can name next episode |
| S7 | Submission | industry skill (not distilled) | 20-minute pitch, one-page leave-behind, platform list | one show per meeting |

Feature craft still applies (dialogue, value turns, character, premise). Rollback: no act out for episode two at S4 = S1 engine fault; stuck dialogue at S6 = S2 web lacks stakes.

## 5. Per-stage minimum actions

Read each doc's workflow and checklist first.
- **1:** the 12-step procedure in 02. External material (song, news): skeleton and imagery only; invent the rest.
- **2:** ending first; scale BS2 to target pages (theme 5%, catalyst 11%, act two 23%, B story 27%, midpoint 50%, all-is-lost 68%, dark night 68–77%, act three 77%); fill `beat | page | one line`; name the midpoint illusion and its all-is-lost reverse. Setup ≤25%, catalyst ≤p.20, act three shortest.
- **3:** one three-dimension row per major character; the binding and whose trait must die to break it; ≥1 antagonist knife; the hero's shackles.
- **4:** row `scene | INT/EXT · place · day/night | one line | value open→close | slot | +/- | ><`. Values are signed pairs (`trust(-)→trust(+)`); `><` = who wants what, who blocks, who wins. Unmoved value = cut. 40 cards in four quarter rows; <6 in act three → recheck the B story.
- **5:** update "Progress" daily; fix design flaws in the bible first, then the script.
- **6:** each failed item → `checklist-question | scene/page | problem | fix`; order 03 → 04 → 06 → 05 → 07 (A + adopted convention) → Snyder's rewrite questions (03). Act two first, then dialogue, then format.
- **7:** logline and synopsis from "Premise and theme"; PROBLEM.

## 6. Exit checks, subagents, language
- Checks are **advisory**: a skip is marked beside "Current stage" and recalled before stage 5; the AI self-runs each checklist and logs failures; quantify. **The client's format beats any doc's convention** — doc conventions fill blanks only; compress, never exceed.
- **Subagents:** never split stages (premise, structure, character are one); parallel only for stage-6 reads (one read-only agent per checklist) and lookups; only the main line writes the bible. **Language:** answer in the question's language; anchor terms to the English originals in knowledge/screenwriting/12-terms.md, never coin translations; untranslatable = original + gloss; the script stays in the work's language (07).

## 7. Compact story-bible.md template

```markdown
# <Title> story bible
## Project info
- Type / medium · entry path · audience and budget tier
- Comparables: 3–5 with climax notes
- Files: outline, treatment, script (name + date)
## Current stage
- Stage: [0–7 / S0–S7]; skipped: … · Next step: one sentence
## Settled decisions (changes → log)
- Premise · controlling idea · ending · hero and antagonist · other closed items
## 1 Premise and theme
- Spark · theme sentence · what-if · premise (trait + leads to + outcome) · controlling idea (value + cause)
- Third track: desire ; false belief ; primal scene ; three turning scenes
- Theme word, stance start→end (hero; antagonist) · dramatic core
- Five questions: who / opponent / why / what changes / why now
- One-sentence story · logline · world rules (first 25 pages)
## 2 Structure
- Ending · opening image · plot points I/II · midpoint kind + all-is-lost mirror
- BS2 page table · act ratios · subplot vs. controlling idea · climax image · ending type
## 3 Character and conflict
| Character | Physiology | Sociology | Psychology | Category | Stance on theme | Relation to hero |
- Binding + what breaks it · antagonist's knife · hero's shackles · growth ladder · image system
## 4 Scene list
- Step-outline file · scenes · cards (act three: n) · cut scenes and why
## 5 Draft progress
- [date] scene x / page y
## 6 Revision
| Target | Source checklist | Status |
## 7 Submission
- Logline · synopsis file · PROBLEM result · target
## Decision log
- [date] what ← why
```

**Series supplement** (replaces 2–3): **S1 Engine** — the S1 row, with the core question as "How will X keep doing Y in a world that Z?" and a stress test: three episodes listable after the pilot. **S2 Web** — `character | specialty | want | can lose | bound to | rationality axis | landmine (unspoken fear/desire, detonation episode)`; season question; tentpoles start/mid/finale. **S3–S4** — the table-row deliverables, plus bible tier (minimal/rolling/full) and pilot closer (launch the franchise / final montage / final discovery).

## 8. Anti-patterns
Idea straight to script (fake treatment) · rewriting the bible each session or re-debating settled items · reasoning in the bible · ten questions at once · exit checks as refusal · stages by subagents · wrong output language, or the discussion language overwriting the script's · coined terms.

## 9. Self-check
(6 questions, as in the source)
1. Is there a `story-bible.md` here, and did I read stage / settled decisions / log?
2. Did this session advance at least one deliverable and write it back?
3. Can the bible still be read in one sitting?
4. Did any settled decision change without a log line?
5. Does the bible end with "Next step:"?
6. Output language matches the question, terms anchored to knowledge/screenwriting/12-terms.md, script language intact?
